CH4 PLUME / HOW IT WORKS

The physics, the cleaning pipeline, and how real readings flow through

Model Field Tests How it works

This project detects faint methane (CH₄) near a fenceline using a low-cost Figaro MOX sensor. There are two halves: a forward model that predicts what a plume looks like, and a field-test tool that takes in real sensor readings, cleans them, decides whether a plume was detected, and stores the result.

TWO SHAPES OF DATA why the model graph and a real reading look different

▣ THE MODEL — a field over space

Given a guessed source, wind, and weather, the model predicts methane at every point on a map at once. That is the smooth contour on the Model page — a time-averaged snapshot.

◷ A REAL READING — a series over time

A single sensor sits in one spot and reports ppm over time. You see a plume as a bump rising out of the background as the wind carries it past. That is what each Field Test graph shows.

So real measurements live on a ppm-vs-time graph — one per field test — not directly on the map. The map stays the model/reference; later (the Week-3 inversion) real data can estimate the source and put it back on the map.

THE FORWARD MODEL steady-state Gaussian plume · Briggs (1973) σ
C = Q / (2π·σ_y·σ_z·u) · exp(−y² / 2σ_y²) · [ exp(−(z−H)² / 2σ_z²) + exp(−(z+H)² / 2σ_z²) ]

Concentration falls off as the plume spreads (the σ widths grow with distance) and as wind u dilutes it. The last bracket is ground reflection — the ground acts like a mirror. The knobs:

Q emission rate (g/s) — everything scales with it; the main unknown the inversion will solve for.  ·  u wind speed (m/s) — more wind, more dilution.  ·  H release height (m).  ·  stability A–F — how turbulent the air is (sets how fast σ grows).  ·  wind_dir the from-direction that aims the plume.

Background CH₄ is 1.9 ppm (NOAA); the signal of interest is only a few ppm above that. Operating range is roughly 10–200 m, and sub-100 m values are order-of-magnitude only (the open-country formulas were validated farther out).

CLEANING A REAL READING four steps pull the tiny signal out of the mess
1

Weather correction

MOX sensors drift with temperature & humidity. If those columns are in your CSV, we fit and subtract the weather-driven part first.

2

Baseline subtraction

A slow rolling low-percentile estimates the wandering “zero”. What’s left is the excess above the local floor — the plume.

3

Smoothing

A centred moving average shrinks random noise by ~√N while a real, sustained bump survives.

4

Detection

We flag an event only when the excess stays above 3× the noise floor for several samples in a row — one spike is just noise.

DETECTION & THE NOISE FLOOR the one number everything hinges on

“Detectable” means the cleaned excess clears 3 × noise floor. With the assumed 0.30 ppm floor that threshold is 0.90 ppm — the same cutoff used on the model graph, in the feasibility sweep, and in every field test, so the answer is consistent everywhere.

Important caveat: that 0.30 ppm noise floor is an assumed placeholder until the real Figaro is characterised. The whole detection margin moves once it’s measured — which is exactly why each field test lets you set its own noise floor, and why the harder, lower-ppm Melissa site is the real test of the design.

Only the raw readings are stored; the cleaning is recomputed each time you open a test, so settings (like the noise floor) can be retuned without re-uploading. Data persists in Railway Postgres when configured, or a local file otherwise.
